# SDTM 学习记忆与跨 Agent 接入

UniMind.ai 保存学生的正式学习状态。DSH 和外部 Agent 共用 `recall_learning`。新凭证绑定当前学习空间的学习身份，可读取该空间中有权限的项目、路径概况、历史问答、听课位置、外部学习记录及已授权笔记。Agent 可把返回的项目 ID 填入 `project_id`，继续读取项目的知识图版本、最近浏览节点和任务。记录带有原始 ID 或版本，以便重新确认。课程可见性、笔记删除和身份范围在读取时核对。

## 关联听课和笔记

在项目的「关联学习记录」里选择课程或笔记，无须先发消息引用。已看的课程读出实际播放位置。关联尚未播放的课程只返回课程信息，进度为未知。笔记按原文实时读取，查询能定位到较长笔记中的相关段落。解除关联后，该项目停止通过这条关联读取来源，原笔记和课程进度保留。由课堂问答或学习路径形成的其他引用仍按各自的权限规则读取。小宇通过项目召回读过笔记时，该对话的正文会沿用笔记对话的外部召回限制。读过课程时，课程解绑或失去访问权也会限制关联对话的后续召回。

## 跨应用使用

1. 在启用连接功能的环境打开「设置 → 高级 → 外部 Agent」。直接在本页查看 MCP 地址，为每个客户端创建独立凭证。悬停在标题旁的感叹号上可查看接入步骤。新凭证授权当前学习空间，默认只读，有效期 30 天。笔记共享和外部写入各自授权。历史项目凭证按原范围使用，可在同一页面断开。
2. Codex 使用远程 Streamable HTTP。把凭证放入客户端的安全环境，环境变量名可用 `UNIMIND_LEARNING_MEMORY_TOKEN`。运行下列配置命令，URL 取自设置页。

   ```sh
   codex mcp add unimind-learning-memory --url 'https://<unimind-host>/api/ai/learning-memory/mcp/' --bearer-token-env-var UNIMIND_LEARNING_MEMORY_TOKEN
   ```
3. WorkBuddy 在「连接器 → 自定义连接器」填写同一个服务地址，选择 Streamable HTTP，通过客户端提供的凭证或请求头配置传入 `Authorization: Bearer <凭证>`。部署到 WorkBuddy 开放平台时使用其 token 授权模式注入凭证。
4. DSH 使用服务端确认过的当前用户和会话直接调用同一个读取模块。外部客户端通过 `record_learning_checkpoint` 记录学习经过，传入稳定的 `request_id`，同一凭证重试时返回同一条记录。学生可在设置中断开连接。正式成绩、掌握度、计划和机构权限继续由各自的业务入口维护。

设置页使用当前部署的后端源站生成 MCP 地址。正式 UniMind.ai 使用 `https://unimind-ai.com/api/ai/learning-memory/mcp/`，本机测试使用对应的回环地址。Codex 的本机 OAuth 回调仅用于把登录结果交回客户端。接入时填写的是设置页里的 MCP 服务地址。

### 从续学摘要追到原记录

`recall_learning` 同时提供当前空间的练习记录、错题状态和复习历史。`read_learning_source` 可用 `practice`、`wrong_answers`、`review_history` 和 `conversation_history` 按关键词翻页。用返回的 `exam:<id>` 读取批改状态和逐题摘要，再用 `answer:<id>` 读取题干快照、学生原作答及可见反馈。尚未批改的作答保留原文，分数和正确性为未知。

旧问答可用 `conversation:<UUID>` 逐页定位，再用 `message:<id>` 读取长消息正文。课程用 `course:<id>` 按关键词或时间定位讲稿，返回讲稿版本、播放位置与有权限的课程页面。课件和参考资料从课程页面打开。响应中的 `next_offset` 用于下一次读取。直接读取和续学摘要共用权限检查，课程撤销可见后，已记录的下游转述也受限制。

### 预注册客户端的 OAuth 接入

配置 `UNIMIND_LEARNING_MEMORY_OAUTH_ORIGIN` 为对外 HTTPS 源站，配置 `UNIMIND_LEARNING_MEMORY_OAUTH_CLIENT_IDS` 为允许的客户端 ID 列表。在 Django OAuth 应用中为每个客户端单独注册授权码模式和回调。授权端点是 `/api/ai/learning-memory/oauth/authorize/`，换票和续期端点同为 `/api/ai/learning-memory/oauth/token/`。服务通过 MCP 的 401 响应提供发现入口。授权、换票、续期时的 `resource` 均填写完整的 MCP 地址，保留末尾斜杠。

登录后授权一个学习空间。只有一个可用空间时直接确认，多空间时先选授权空间。`learning.memory.read` 为必选范围，`learning.memory.notes` 和 `learning.memory.write` 单独申请。S256 PKCE 必填。授权码单次有效，访问凭证有效期最多一小时，续期凭证轮换，授权期最长 30 天。重放已用的续期凭证会断开该连接。学生可随时在设置中断开连接。网站登录的客户端范围保持独立。

- Codex 为预注册的公开客户端。先用 `codex mcp add unimind-learning-memory --url "$MCP_URL" --oauth-client-id "$CLIENT_ID"` 取得该服务的 `OAuth callback URL`，在应用中登记相同的回调地址，再完成登录。回环地址允许客户端选择本机端口，回调路径必须一致。标准发现会带上 `resource`，配置这一流程时无需重复传 `--oauth-resource`。
- WorkBuddy 使用 `auth_mode: "server-side"` 和 `server_auth.auth_type: "oauth2_code"`。按平台生成的实际回调地址预注册保密客户端。`provider_config` 启用 `pkce_enabled`、`refresh_enabled`，并在 `authorize_extra_params`、`token_extra_params`、`refresh_extra_params` 中填相同的 `resource`。`mcp.json` 使用 `streamableHttp` 和同一个地址。先配只读权限，通过实机后按项目需要增开笔记或写入范围。[WorkBuddy 官方接入规范](https://open.workbuddy.cn/docs/connector)

## 认证复查试点

- 先运行数据库迁移。只在指定候选环境启用 `UNIMIND_SDTM_TASK_MEMORY_MODE=active` 和 `UNIMIND_SDTM_STRUCTURED_DIAGNOSTICS=true`。设置 `UNIMIND_SDTM_DIAGNOSTIC_PROJECTS` 为首批项目 ID 的逗号分隔列表。该列表限定认证诊断，任务记忆模式仍属于环境级配置。
- 使用 `manage.py import_sdtm_certified_material manifest.json --project <id>` 验证已审核材料，确认后加 `--apply`。清单含 `publication_id`、`method`、`tasks` 和 `examples`。方法提供 `key`、`instruction`、`requires`、`source`。每个任务条目提供 `task_id`、`schema`、`bindings`、`decisions`。例题提供 `card` 和相同的后三项。同批操作共享事务。
- `UNIMIND_LEARNING_MEMORY_CONNECTORS=true` 独立开启学习空间授权、跨来源召回及知识节点浏览位置。停用该开关即停止外部入口。停用 SDTM 任务记忆后，新回合和重试从普通项目状态读取，迁移后的数据及成绩保留。

## 如何判定下一步

先从真实站内学习轨迹选取同一项目的「听课 → 记笔记 → 问答 → 外部写入 → 小宇续学」案例。加入旧会话、无关项目、笔记删除、课程取消可见、精确同定义换版和实质换版。记录找到的原来源、恢复位置、完成下一步、误引用、工具调用数和延迟。只展示有权限、可核对的证据。站外和线下学习通过授权 Agent 的自报或后续产品接口进入，当前站内记录没有对应输入时保持未知。

研发对照采用同模型和预算的普通检索，以及使用相同资料的普通关系实现。比较目标是跨来源后的正确续学、同题披露能否及时引发换题，以及更正后的证据资格能否正确传播。若召回缺失，先核对是否存在项目来源关系，再检查检索排序和模型使用。教学收益用未来独立作答及延迟复查验证。已有工程差异来自来源约束、任务和知识版本的精确延续、以及更正证据后保留原成绩。目前的关键词召回和受审核的方法目录仍是可比较的基线。

空间召回涵盖未关联项目的听课活动和获授权笔记。项目关联用于在该项目内缩小读取范围。同一账号下不同机构空间及个人空间各自维护授权。旧的笔记陪聊缺少完整引用来源，跨应用读出会排除这类历史正文。原记录保存在原有系统，每次召回返回相关且有权限的摘录。历史对话、笔记和观看记录的覆盖率，应使用试点学习轨迹中的应记录事件作为分母，再核对实际落库、可检索和正确续学三个结果。自由文本自动证据确认、从多人后续作答归纳公共方法和真人长程学习效果需另外验收。

## 2026-11-25 首轮验收

在隔离候选环境使用合成学员、课程和笔记。Chrome 完整走通课程播放及进度写入、创建笔记、项目关联、发放连接凭证、解除笔记关联和断开连接。通过真实 Codex 客户端读取课程与授权笔记，并以同一个请求编号写入两次，得到同一条检查点。跨会话的小宇通过原 DSH 路径读回同一批资料。该浏览器流程使用固定的模型协议响应。

另用一次真实 DeepSeek 回合验证续学判断。学员只说「接着上次学」，模型调用 `recall_learning`，找回此前已标注第 1、2 期、尚需核对第 0 期的检查点。答复正确区分了第 0 期和未来期的折现，给出了画时间轴的下一步，并成功保存。这是一个合成学习案例的模型结果。

预先加入的反例复现了经历史答复转述笔记时，未授权的 Agent 仍可能看到该段内容。候选分支现记录 DSH 使用过的召回来源，后续按笔记和课程范围复核历史。解除关联后测试确认不再读到转述，笔记原文保留。断开凭证后试验请求返回 401。PostgreSQL 上两条学习记忆冒烟和 14 条 DSH 冒烟通过，包含停用时保留已有记录。

后续补齐预注册 OAuth。PostgreSQL 通过 `0050` 和 `0051` 迁移，学习记忆、OAuth 与 DSH 的 18 条联合冒烟通过，包含公开与保密客户端授权、绑定项目、续期、重放撤销和账户全端登出失效。Chrome 从真实登录页回到授权页后，Codex CLI 成功授权，并在测试访问凭证到期后自动续期和读回所选项目。

当前候选可进入受控试点。全量上线还需 WorkBuddy 开放平台注册与实机联调、获授权的真实课程和学员试点，以及候选环境的线上检查与回退演练。研究对照中来源对象版与普通结构化版均完成 4/4 个合成剧本，原路径完成 3/4。两种结构化版的模型输入和回答相同，本轮没有观察到来源对象存储带来独立的学习质量增益。

## 设置入口与续学复验

Chrome 在「设置 → 外部 Agent」选择项目后发放只读及读写凭证。切换到其他项目时，原凭证和连接列表离开当前视图。切回后可管理原连接，一次性凭证不会再次显示。真实 Codex 读回授权笔记、写入一个检查点，重试仍返回同一条记录。Claude Code 的 MCP 健康检查返回已连接。解除笔记关联后召回结果不再包含该笔记，设置中断开连接后原凭证返回 401。

在同一隔离试点的数据副本中，新建一个小宇会话并启用实际 DeepSeek 模型。模型调用 `recall_learning`，找回浏览器留下的 2 秒左右课程位置、关联笔记里的「今天到账的 240 元」自检例子，以及 Codex 实际写入的时间轴任务。回答还区分了学习活动记录和独立作答证据。本次课程和学员均为合成样本，回答已保存。真实学员试点和 WorkBuddy 实机仍待验收。

改为空间授权后，Chrome 在同级的「个人」和「高级」分类下核对了「外部 Agent」入口。MCP 地址直接显示。真实 Codex 通过新凭证读回同一机构空间的两个项目、未关联笔记和观看记录。同账号的个人空间无法列出该连接。PostgreSQL 迁移 `0052` 与 19 条学习记忆、OAuth、DSH 冒烟通过，覆盖旧项目凭证的权限范围与默认会话读回外部记录。

接入原记录后，真实 Codex 从合成学员的续学摘要定位到练习，读回原作答、批改反馈、错题次数、复习间隔和课程讲稿。PostgreSQL 20 条联合冒烟通过，核对了历史题干快照、未批改状态、长问答分页、跨用户隔离和课程撤销后的访问限制。

合入 2.0 后，隔离 PostgreSQL 从 2.0 升级至 `0052`，36 项定向冒烟通过。新版小宇的流式入口用合成学员和固定模型响应验证了续接课程位置、读取原讲稿、沿用本轮笔记权限，以及保存可复核的来源版本。验收同时复核了轮询转流式、学习计划确认、知识路径、学习进展和检查题。
