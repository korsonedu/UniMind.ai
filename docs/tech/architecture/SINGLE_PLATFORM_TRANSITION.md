# 科晟单平台：机构字段过渡清单

2026-10-18。本次停止 B 端入口并更换权限和内容边界，未物理删除多租户结构，未修改或归并历史机构数据，未执行生产迁移或部署。

## 已实施的访问边界

- 学习权限由 `users.learning.is_course_student` 与现有功能开关共同决定；非课程学员只取得 `ai.assistant` 和本人账号服务能力。权限组和额外权限不能越过课程状态或管理员身份。
- 历史 `owner`、`teacher` 不再授予管理能力。仅 Directus 两人映射中的既有平台超管保留后台权限，且仍须启用、具备 staff/superuser 身份及无机构；映射缺失也拒绝后台访问。保留每人独立操作身份。
- `filter_tools(..., user=None)` 保留原调用签名兼容，缺少用户时返回空工具。非学员无学习工具；课程学员按功能开关；管理员取得工作台注册工具。执行器再次校验当前用户能力和请求许可，不依赖模型自行遵守。
- `UNIMIND_CONTENT_INSTITUTION_ID` 必须显式配置。正整数表示该机构；显式 `global` 表示 `institution IS NULL` 的历史内容分区；空值拒绝内容访问。管理员无机构、传入预览参数或缺配置均不能扩大到全站。此配置只确定既有内容范围，不迁移记录。
- 激活、机构加入/邀请、角色变更、机构切换/套餐变更、机构写入和外部 API 入口返回 410 或仅保留管理员只读查询。旧 API Key 不再认证，历史凭证与日志保留。
- 小宇 dashboard、memory、practice、grading 直接请求受学习功能权限校验；本人对话历史仍可读取。批改和工具中的课程、题目、知识目录、文章查询均保留明确内容过滤。

## 仍保留的依赖及清理条件

| 依赖 | 暂时保留原因 | 后续清理条件 |
| --- | --- | --- |
| `users` 的用户 institution、机构、邀请、审批、激活码、套餐、使用和审计模型 | 历史账号归属、订单与操作证据不能丢失；停用的是入口 | 逐账号核对身份及两名操作者，导出并保留历史审计，确定可归档对象后追加迁移 |
| `courses`、`articles`、`quizzes`、`faq_system` 内容外键及 serializer/queryset 过滤 | 作为单平台内容归属兼容层，防止无机构管理员看到所有历史租户 | 逐表确定科晟资源映射，检查 parent/知识点/课程/题目关联，验证引用和文件访问后再变更模型 |
| `quizzes` 的 Memorix、IRT、学情快照与配置 | 学习状态、题目参数和演化历史与旧内容关联 | 对照用户、题目和知识点 ID 核对；保持个人历史，不跨账号合并，不重置调度状态 |
| `ai_assistant` 的 Bot、记忆命名空间、经验、轨迹与缓存 | 历史会话与个人记忆仍有效，租户命名空间仍在既有状态中 | 制定逐项 namespace 与历史恢复映射；禁止通过清空 institution 或重新生成记忆冒充迁移 |
| `quizzes` 内容管线与 Celery payload | 既有待审核产物、任务状态和任务引用需要恢复 | 核对任务实际 content scope、payload 内 IDs、结果文件及未完成任务后再迁移 |
| `study_room` 聊天、`notifications` 通知与 `core` 分析事件 | 历史交流和审计归属仍有保留用途 | 明确保留期、个人归属和科晟学习分组范围后归档 |
| `payments` 订单/订阅字段及旧权益记录 | 真实历史订单、回调幂等和对账不能覆盖成新商品语义 | 完成对账及旧权益兼容方案；机构/课程新销售已停，不能据此删除历史订单 |
| `backoffice` 管理内容过滤与 Directus 桥接 | 管理员教学任务需要明确内容范围与独立审计 | 保持两人签名校验；内容归属确认后与 Django 查询规则同步迁移 |
| 前端 `institution` 字段、旧页面与 API 类型 | 部分客户端仍消费兼容字段，旧页面文件存在不代表恢复 B 端 | 逐项确认已无可达入口、无运行依赖，再删除页面/类型；不能只隐藏 UI 而保留写入 |
| migrations、种子及历史管理命令 | 已有迁移历史不能删除重建；旧运维脚本可能仍引用机构 | 审阅所有写入型管理命令并更新运维流程；未核对前禁止运行批量归属或清空机构脚本 |

本地盘点发现 32 个 Institution 外键或一对一字段。完整明细由下方只读命令按当前数据库生成，避免提交容易失效的静态数据快照。旧记忆命名空间、缓存、配置、商业模型和运维命令仍属于后续物理清理范围。

## 本地只读数据发现

当前本地有机构 3、4、5，名称分别为“宇艺示范学院”“宇艺教育”“1”。这不能证明生产状态。

| 内容 | 全局 | 机构 3 | 机构 4 | 机构 5 |
| --- | ---: | ---: | ---: | ---: |
| 课程 | 8 | 1 | 0 | 0 |
| 知识目录 | 8875 | 424 | 483 | 483 |
| 题目 | 304 | 67 | 4 | 0 |
| 内容任务 | 115 | 4 | 1 | 0 |

该分布不支持猜测科晟对应哪个机构，也不支持把所有历史机构合并成全局。快照中内容范围为 `UNCONFIGURED`，因此不能将本地严格拒绝内容访问误报为已完成真实账号接入。

生产核对时执行只读命令，并另存输出：

```sh
cd backend
python manage.py inventory_institution_dependencies > institution-inventory.json
```

命令只读取 Institution 和关联行数；新模型表尚未迁移时列入 `pending_tables`。命令不创建用户、不改角色、不运行迁移、不删除或归并记录。JSON payload、缓存键、对象存储路径、Directus 外部数据以及跨表引用仍需逐项核对，SQL 外键数量不能代替这些检查。
