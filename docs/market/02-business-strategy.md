## 一、市场定位

### 1.1 市场格局

中国教育科技市场呈三层结构：

| 层级 | 代表 | 特点 |
|------|------|------|
| C 端 AI 教育 | 学而思、作业帮、猿辅导、科大讯飞 | 面向家长和学生，AI 辅助做题，红海竞争 |
| B 端传统 SaaS | 校宝在线（25 万+ 校区） | 主打招生和教务管理，AI 出题/AI 教学未被占领 |
| B 端 AI 教学 | UniMind | 唯一以 Agent-Native 架构做 B 端教学闭环的产品 |

**核心判断**：B 端 AI 教学场景是小蓝海。校宝等传统 SaaS 停留在教务管理层，教学核心环节（出题、批改、学情诊断、自适应学习）仍靠人工。UniMind 的切入点是"用 AI 替代教学执行层的人力消耗"，而非"用 SaaS 替代教务管理的纸质流程"。

### 1.2 差异化定位

不做"又一个 ClassIn/校宝"。定位：**AI-native 教育机构操作系统**——传统 LMS 管"教了什么"，UniMind 管"学会了没"。

四个 AI 差异化高地：AI 批改、AI 备课、AI 学情诊断、自适应学习路径。

## 三、商业模式

### 3.1 双轨策略

| 维度 | SaaS 版 | 企业版 |
|------|---------|--------|
| 客户 | SMB 机构 | 中大型机构、教育集团 |
| 收入模式 | 订阅制（月/年） | 一次性 license + 年维护费 |
| 合同复杂度 | 低（标准服务协议） | 高（部署、运维、SLA、数据归属） |
| 运维 | UniMind 集中管理 | 客户自行运维 |
| 数据 | UniMind 服务器，机构物理隔离 | 客户服务器，数据不出内网 |
| 定制 | 无 | 品牌白标 + 二次开发（类似开源模式） |
| 代码 | 闭源 SaaS | 源码交付 |
| 集成 | 无 | 飞书/钉钉/企微集成 |

核心引擎（Memorix、AI 管线、Agent 运行时）两版共享同一代码库，避免 fork。

### 3.2 收入漏斗

```
Free（免费体验，14天全功能）
  → Starter（个人教师/小机构试水）
    → Growth（核心收入来源，机构教学平台）
      → Enterprise（大客户，一次性 license + 年维护费）
```

### 3.3 合同策略

| 客户类型 | 所需文件 |
|---------|---------|
| B2C（个人用户） | 服务协议（ToS）+ 隐私政策 |
| B2B（机构客户） | 标准服务协议 + 隐私政策 + DPA（数据处理协议） |
| 企业版（本地部署） | 部署合同 + SLA + 源码保护条款 + 数据归属条款 |

**已完成**：隐私政策 + 用户协议（`frontend/src/pages/Legal.tsx`，路由 `/privacy` `/terms`），注册勾选同意协议。
**待完成**：机构数据处理协议（DPA）——待机构客户需求明确时再出。

## 四、竞争壁垒

### 4.1 技术壁垒

**Memorix 数据飞轮**：学生每做一道题，算法就更新一次。用户越多、数据越多，预测越精准。新进入者无法用更低的成本复制这种积累。

**四层架构的接口隔离**：通过 MemorySystem 接口强制跨层隔离，任何 handler 都无法绕过 Memorix 直接修改调度参数。这意味着"文档说 Memorix 是节拍器"和"代码强制 Memorix 是节拍器"是同一件事。

**Agent 运行时的高度可扩展性**：新增 Agent 只需写 prompt + 注册。这使我们在学科扩展（金融 → 数学 → 法律 → ...）和角色扩展（学生 Agent → 教师 Agent → 家长 Agent → 学校管理员 Agent）上具有极低的边际成本。

### 4.2 产品壁垒

**转换成本**：学生使用小宇的时间越长，Memorix 积累的个人数据越多。切换到竞品意味着重新从零积累——丢失的不是功能，是正确的复习节奏。

**双端闭环**：工作台出题 → 小宇抽题 → 学生做题 → Memorix 调度 → 教师看班级分析。数据在两端之间流动，单一端的产品无法复制完整闭环。

**Agent-Native 定位差异**：竞品在 C 端用 AI 辅助做题（学而思、作业帮），在 B 端做招生管理（校宝）。UniMind 是唯一在 B 端做 Agent-Native 教学系统的——不是"传统 SaaS + AI 聊天框"，是"以 Agent 为入口、以记忆为时钟的教育基础设施"。

### 4.3 系统演化壁垒

替代式架构（模型产出 → 模型评估 → 模型优化）时间越长越趋近模型自己的标准。嵌入式架构（模型产出 → 教师评估 → 模型从教师反馈中调整）时间越长越贴近使用者的判断。不同机构用同一个系统，半年后系统的行为会不一样——因为每个机构的题库、出题偏好、质量标准，随着教师反馈逐渐形成自己的方向。这件事实质上创造了**按机构递增的切换成本**。

## 六、企业版部署概览

> 详细部署步骤见 `docs/enterprise-deployment.md`

### 6.1 硬件要求

| 环境 | CPU | 内存 | 磁盘 | 适用 |
|------|-----|------|------|------|
| 最小 | 2 核 | 4 GB | 20 GB | <50 学员 |
| 推荐 | 4 核 | 8 GB | 50 GB | 50-500 学员 |
| 大规模 | 8 核+ | 16 GB+ | 100 GB+ | 500+ 学员 |

### 6.2 模块开关

通过 `ENABLED_APPS` 环境变量控制启用模块：

```bash
# 全部启用（默认）
ENABLED_APPS=all

# 企业版精简（不含支付、自习室、文章、面试、FAQ）
ENABLED_APPS=core,users,quizzes,courses,ai_assistant,ai_engine,notifications
```

### 6.3 品牌定制

企业版支持：机构 Logo、主题色、机构名称、自定义域名。

### 6.4 部署方式

Docker Compose（推荐）或 Systemd + Nginx。依赖：PostgreSQL 14+、Redis 6+、LLM API Key。
