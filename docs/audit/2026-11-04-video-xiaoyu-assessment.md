# 视频页小宇功能评估与改进建议

日期：2026-11-04。审查基线：本地 `HEAD 3c11cde`，包含随课问答提交 `611d11c`（PR #16）。本报告评估当前源码，不将本地代码状态等同于生产验证。

本轮只新增报告，没有修改业务代码。现有未跟踪的数据库备份和 `pitch/` 未改动。

## 1. 总体判断

课程小宇已经具备随课学习的核心能力：输入时固定问题位置，服务端选择该位置前后各 30 秒附近的完整讲稿段落，回答可携带讲稿引用，点击可回看，讲解可以保存为个人笔记。它适合继续完善为视频工作区里的学习助手。

当前主要问题在于学习过程的连续性、可发现性和界面一致性。优先解决历史会话难以返回、桌面草稿恢复丢失片段锚点、发送快捷键与设置不一致、讲稿不可用时提示过晚，再统一浮层与输入区。暂不扩展自动出题、主动打断、完整课程总结或新的助手模式。

证据级别：下文“确定”表示可从当前代码直接确认；“风险”表示代码存在相应条件，但实际影响尚需浏览器或真实模型确认。没有开展真实模型质量、性能测量或生产验收。

## 3. 功能、逻辑和交互问题

### F1｜P1｜旧课程会话缺少返回入口【确定】

初始化会读取本课程所有会话，但只自动打开最近一条。面板提供“新对话”，没有会话列表或选择器。“展开文字、公式和历史”只展开当前会话的消息，并不能选择其他会话。主小宇默认历史接口又主动排除课程会话。

结果是学生新建了第二个课程会话后，在正常界面里无法主动找回第一个课程会话。消息仍在服务端，并非已经删除。

建议：在课程小宇标题区提供一个轻量“本课对话”入口，使用现有菜单或抽屉，按时间列出本课会话；保留“新对话”。浮层底部改为“展开本次对话”，避免暗示已经提供完整历史管理。首轮不增加项目、标签、置顶等管理功能。

证据：`CourseChatPanel.tsx:77–83,140–141,200`；`backend/ai_assistant/views.py:519–528`。

### F2｜P1｜桌面草稿恢复后，原提问片段丢失【确定的状态缺口，待端到端复现】

桌面恢复机制持久化草稿文字，但 `draftPosition` 只保存在课程面板的组件状态里。对于“尚未发送”的草稿，重载后可能恢复问题文字，却没有原位置。此时输入区提示重新选择范围，发送按钮仍可用，`send()` 会回退到当前视频位置。

例如在 08:20 开始写“这里为什么折现”，重启后视频位于 12:30，恢复的文字有机会直接按 12:30 发送。已发送且处于待确认状态的请求有原始 payload，不属于同一个问题。

建议：课程草稿文字与片段位置一起保存、一起恢复。兼容没有位置的旧草稿时，先要求点击“改问当前片段”，再允许发送；不要在发送时静默绑定新的位置。仅在既有恢复记录中补充必需字段，不另建草稿系统。

证据：`CourseChatPanel.tsx:45–47,93–115,192–198`；`frontend/src/lib/conversationRecovery.ts:9–13`；`frontend/src/hooks/useAgentConversation.ts:171–176,467–496`。持久化恢复当前仅在桌面桥存在时启用，不能据此声称网页重载也会恢复草稿。

### F3｜P1｜发送快捷键不遵循用户设置【确定】

主小宇读取全局 `sendShortcut`，组合键模式下 Enter 换行。课程面板固定使用 Enter 发送。用户在设置中选择了 ⌘ / Ctrl+Enter 后，进入课程页按 Enter 仍会发送尚未写完的问题。

建议：复用同一个设置和判断规则，保留 Shift+Enter、中文输入法组合状态保护；无需为课程页添加独立设置。

证据：`CourseChatPanel.tsx:192–193`；`frontend/src/components/AgentChatLayout.tsx:145–147`；`frontend/src/pages/Settings.tsx:156`。

### F4｜P1｜讲稿不可用时，界面仍承诺可以结合讲稿回答【确定】

初始化只加载 Bot 和历史。空状态直接显示“我会结合这段课程的讲稿来回答”，并允许发送。服务端则要求转写已完成、所选时间附近存在字幕，否则拒绝。学生通常在写好问题、点击发送后才知道当前不能提问。对学生显示“请完成转写后提问”也没有明确的可执行路径。

建议：利用课程页已有的讲稿状态，在发送前显示“讲稿准备中”“本课暂无讲稿”或“该片段暂无讲稿”；保留输入内容。仍由服务端最终校验，不让前端状态代替授权和有效性判断。暂不自动退化为无讲稿回答，否则需要另外明确回答依据与计费语义。

证据：`CourseChatPanel.tsx:65–91,166–167`；`backend/ai_assistant/services/course_context.py:43–51`；`frontend/src/components/course/SubtitlesOverlay.tsx:15–35`。

### F5｜P1｜桌面回复通知进入错误工作区【确定】

共享 Hook 在回复完成时将通知目的地固定为 `/xiaoyu`。课程面板也调用这个 Hook，但课程对话不会出现在主小宇的默认历史里。开启桌面聊天通知后，点击课程回复通知不能直接定位该回答。

建议：课程回复的通知返回对应课程，并恢复对应会话；普通小宇继续回到其原有入口。只携带定位必需的课程和会话信息，仍复核访问权限。

证据：`frontend/src/hooks/useAgentConversation.ts:825–827`；`backend/ai_assistant/views.py:519–528`。

### F6｜P2｜离开课程页会中止本地流，连续性弱于主小宇【确定机制，影响待实际验证】

主小宇的 Provider 常驻于路由层；课程小宇的 Hook 位于课程页面内部，切换课程或进入笔记会卸载它，清理逻辑会中止本地 SSE。中止本地流不等于服务端一定取消任务，也不能据此推断重复扣费。

建议先保证返回本课后能确认原请求结果、找回原会话，并明确“仍在处理”的状态。网页和桌面的恢复差异需要说明。只有实际使用证明跨页继续显示生成是刚需时，再考虑提升会话生命周期；本轮不建议为此重构所有对话 Provider。

证据：`CourseChatPanel.tsx:38–41,59–63`；`frontend/src/hooks/useAgentConversation.ts:948–960`；`frontend/src/pages/xiaoyu/XiaoYuChatProvider.tsx:11–15`。

### F7｜P2｜一分钟片段和学生所说的“这里”仍有歧义【产品风险】

机制按预期工作：首次输入固定位置，输入和提问不会自动暂停视频。但学生可能播放了很久后才开始输入，也可能继续问上一段推导，而当前视频已进入下一章节。固定一分钟解决了输入过程中的漂移，不能覆盖全部语义指代。

建议保留现有规则，把“已固定 07:50–08:50”放在输入区清楚的位置，提供“回看片段”和现有“改问当前片段”。后续可考虑将字幕选择作为提问依据，先不增加任意区间编辑器。自动暂停不宜成为未经验证的新默认行为。

另外，前后各 30 秒可能包含尚未播放的内容，界面应如实称为“提问片段”，避免称为“刚听过的一分钟”。

### F8｜P2｜讲稿搜索结果与精确引用的回看体验不一致【确定】

回答中的快照引用可以定位具体字幕，但 `search_asr` 的结果卡片只链接课程根地址，虽然卡片文字已经显示起止时间。点击搜索结果未必回到所显示的片段。

建议给经服务端授权的搜索结果保留真实开始时间，用已有 `?t=` 能力定位。它应当保持“搜索结果”的含义；不能绕过当前快照校验，把搜索结果伪装成当前回答已核验的精确讲稿引用。

证据：`backend/ai_assistant/services/dsh_cards.py:31–34`；`frontend/src/pages/VideoLesson.tsx:259–269`；`frontend/src/components/course/courseCitations.tsx:14–23`。

## 4. 设计评估：与当前主站保持一致

采用当前代码中的设计变量和主小宇实际样式作为实现基准。`frontend-design-v2.md` 用于理解“安静、紧凑、精确、内容主导”的方向，其中早期尺寸和验证记录不自动代表今天的界面。

### 4.1 保留现有主框架

保留功能侧栏、课程目录、统一圆角主工作区、视频与可调学习侧栏。桌面主面板当前为 16px 圆角，手机 12px。课程助手位于工作区内部时不再增加一层外框、圆角和阴影；当前右侧模式已经这样处理，应延续。

消息正文也已经复用主站样式：靛蓝用户气泡、透明助手正文、统一 Markdown 和公式。虽然组件传入 `compact`，共享 CSS 将正文覆盖为 `--um-font-chat`；不能把它误判为整段聊天只有 12px。

证据：`frontend/src/styles/app-shell.css:4,37`；`frontend/src/styles/native-agent.css:180–201`；`frontend/src/styles/course-lesson.css:122–125`。

### 4.3 输入区的推荐排列

输入区保持主小宇的操作习惯，但增加课程必需的片段信息：

```text
小宇                         本课对话  ·  显示方式

问题与讲解
具体解释句中的讲稿引用
讲稿参考范围                         存为笔记

已固定 07:50–08:50                    回看／更新
┌────────────────────────────────────────────┐
│ 问问这段课程……                              │
│                                  圆形发送  │
└────────────────────────────────────────────┘
```

这只是信息层级示意，颜色、字体、图标、间距和控件直接使用现有系统。无需引入新字体、图标库、动效库或组件主题。

当前输入底行将片段提示、更新按钮、发送按钮并排放置；右侧栏默认宽 300～320px，内部还需扣除左边距与输入框边距。较长时间范围、大字模式和手机窄屏下存在拥挤风险。片段信息独立成一行，发送按钮设置不收缩，优先解决这个问题。没有浏览器截图，暂不认定已出现具体溢出。

### 4.4 浮动、侧栏、手机与全屏

桌面建议让右侧模式承担长解释、公式和连续追问；浮动模式承担看课时的快速提问。先保留当前默认浮动和已保存的用户偏好，是否改变新用户默认值需结合使用反馈，不由审查直接决定。

手机建议优先让视频下方的助手或现有抽屉承担完整输入，避免展开浮层和软键盘同时遮住视频及播放操作。第一步可以先修尺寸、布局、底部安全距离和真实布局名称，不必立即新增第三种模式。

标准全屏当前只针对视频容器，而助手在容器外；原生视频全屏也有平台限制。先提供清楚的“退出全屏后提问”路径，是否需要全屏内助手作为后续需求，不要求本轮强行嵌入。

## 5. 前端实现与回答依据

1. **局部复用，避免大改。** 保留 `CourseChatPanel` 的课程语义，继续复用共享消息、公式、工具过程、引用校验和恢复机制。只让输入外观、发送规则与现有主小宇保持一致，不将整个 `AgentChatLayout` 搬进狭窄侧栏，也不为两个输入框先建通用配置框架。

2. **播放更新与消息渲染有耦合风险。** `VideoLesson` 的时间更新会触发页面重渲染，课程面板未建立 memo 边界，且每条消息每次都创建新的 `markdownComponents`，削弱了 `ChatBubble` 的 memo 效果。长会话与公式较多时应做一次轻量性能观察，再用稳定回调及合适的组件边界处理；当前没有证据声称播放已卡顿。

3. **不要无条件重构历史加载。** 当前一次加载本课程历史，且消息 metadata 包含讲稿快照。历史多时负载可能增长。补“本课对话”时先观察实际返回规模，必要时按会话加载，避免为了假设中的大规模历史先建设复杂缓存。

4. **能力边界须在用户侧可理解。** 当前默认依据是讲稿文本，不能保证识别仅出现在视频画面中的板书和图表。Prompt 已明确要求说明此限制；界面可以简短注明“结合本段讲稿回答”，并在问题涉及画面时请学生补充文字。当前输入框没有图片附件入口，因此不能承诺已经支持截屏问图。

5. **模型上下文会截取。** DSH 本轮上下文将历史截为最近 8 条、每条最多 800 字。多轮长推导可能丢失前提；这需要实际模型对话检查。先在课程 Prompt 中要求缺失前提时澄清、需要其他位置时限定本课检索，不应直接增加所有上下文预算或声称模型记住整节课。

6. **状态文案要符合真实阶段。** 当前 `loading` 总体显示“正在看这段讲稿”，实际也可能在等待模型或运行工具。建议区分“正在处理”和已有可用的具体工具状态；成功、错误、待确认和讲稿不可用使用现有提示样式，不以持续发光动画代替状态。

7. **保留现有服务端边界。** 课程可见性、消息归属、账号隔离、同请求重试和讲稿快照引用已有实际实现。新会话入口、通知定位与片段链接应接入这些边界，不能只凭前端 course ID 放开数据读取。

来源：`VideoLesson.tsx:249–252,394–401`；`CourseChatPanel.tsx:94–98,169–178`；`backend/ai_assistant/services/dsh_xiaoyu.py:34–51`；`backend/prompts/ai_assistant/course_context_prompt.txt`。

## 6. 实施顺序与最小验收

| 顺序 | 范围 | 最小可见结果 |
| --- | --- | --- |
| 第一批：修正使用行为 | F1～F5，优先桌面草稿锚点和发送快捷键 | 原问题仍对应原片段；Enter 行为与设置一致；本课旧会话可返回；不可提问原因提前可见；通知返回正确回答 |
