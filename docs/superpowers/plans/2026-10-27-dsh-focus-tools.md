# 自习专注查询迁入 DSH

> 使用 superpowers:executing-plans，最小实现、定向冒烟、一次最终复核。

**Goal:** 在小宇中查询本人当前自习状态及最近专注历史，复用现有自习室权限和统计口径。

**Architecture:** 开放已有 get_study_status、get_focus_history，单独 focus 工具组；每次模型候选仍不超过 8 个。服务端认可的数据转为现有 data_card，链接仅允许实际 /study 路由。

**Spec:** 用户继续迁移能力的指令、完整规划的学生学习数据能力；不允许 Agent 修改笔记。

## 约束

- 继承 study.room 权限、本人 user id 绑定；客户端传入他人 id 不生效。不开放 save_session_note。
- 不新增计时器/Redis 状态或模型调用；沿用自习室的确定性到期落库处理，它是原统计方法的幂等维护，并非模型指定的写操作。
- 自习专注时长与听课/练习学习记录分别展示，不合并数字或宣称覆盖线下学习。
- 无正式 Redis/真实学生数据验证；定向冒烟模拟当前 Redis 快照，实际查询临时数据库。

## 实施与验收

- 学生已鉴权业务工具由 17 增至 19；focus 独立组含自习状态、专注历史及原学习记录查询，模型仍通过原生发现切换分组，候选上限 8。注册学生或禁用 study.room 的账号不获得两个新工具。
- 复用现有 user_id 绑定及统计；新增两类 data_card 和 /study 精确路由许可。卡片明确区别自习计时与听课、做题、线下学习；历史仅汇总已结束的计时。
- 一次独立复核指出到期 Redis 快照会把本次时长误示为 0。真实临时数据库加到期快照先复现，再修复为到期说明和已落库今日汇总；没有推算、覆盖原计时规则，没有追加复审。
- 原生 SDK/ASGI 实际执行两个查询，恢复两张受控卡片；数据来自临时 SQLite，当前 Redis 快照显式模拟为空。本人/他人、已结束/活跃/到期、权限停用、候选预算与原只读/路由定向检查通过。
- 扩展原生验证时，后台记忆落库引起下一轮 context version 改变，已有保护正确拒绝该轮；夹具先等待记忆任务完成再检查重放和专注调用，未弱化版本保护。
- 同时补查记忆候选在模型处理期间被删除原对话的情况：新增检查先失败，再于事务中锁定本人原会话、确认原用户消息仍存在，原子写入提取日志与候选；迟到候选被丢弃。该修复做了定向故障冒烟及原生正常落库检查，没有宣称跨节点并发压力已验收。
- 最终相关后端 11 项冒烟、实际 SDK 两查询卡片、既有正式 SSE/标题/幂等/删除及评分链路通过。未访问真实 Redis、真实学生或发布生产。
