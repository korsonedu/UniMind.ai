# DSH 服务端会话发现实施计划

> 使用 superpowers:executing-plans 连续实施，只做必要冒烟，一次独立复核。

**Goal:** 同一学生在新标签页/新客户端通过站点身份发现并恢复已有会话，无须从另一设备复制 session_id。

**Architecture:** SessionStore 返回当前业务源/用户目录下最多50项元数据（ID、首条用户消息摘要、更新时间、消息数）；不发原生状态/凭据/全文。站点 GET sessions 经既有短凭据 worker 读取；React 站点模式选择已有会话，沿用现有恢复和删除路径。

**Tech Stack:** 既有 Django/DSH worker/SessionStore、React。

**Spec:** 完整规划 v1.2 第六、十四、M0身份/会话隔离；现有站点会话入口。

## Constraints / ruling

- 默认关闭开关、当前学生身份与运行源隔离保留，不部署、不改正式小宇。
- 会话发现与恢复不调用模型、不扣 AI 周次数；不新增留存时长、跨节点存储或分页平台。
- 只返回当前账号元数据，按最近更新时间最多50项；损坏/非法路径不影响其他有效会话；清空身份时同步清空列表与在途请求。
- 暂时限制50项是开发阶段显示预算，不能宣称完整正式历史/留存治理已完成。

## Review Focus

- 目录/文件或 session_id 越权不会返回他人/另一来源的会话。
- 列表只含受限摘要，不泄漏原始事件、内部提示词、模型配置和凭据。
- 切换身份/旧响应晚到不会回填另一学生列表或对话。
- 删除会话后列表不保留可恢复入口，读取仍由服务端重新鉴权。
- 无浏览器 session ID 的新标签页可恢复服务端已有会话，且不产生模型调用/扣次数。
