# 诊断作答与人工答疑确认

> 使用 superpowers:executing-plans 连续执行；只做必要冒烟和一次独立复核。

**Goal:** 小宇提供可作答的诊断卡和可编辑的人工答疑草稿，只有学生确认才落成绩、初始化 Memorix 或发布工单。

**Architecture:** 复用原诊断抽题、确定性判分、Memorix 初始化及 FAQ 模型。DSH 的 run_diagnostic 仅允许 generate，create_faq_ticket 仅准备草稿。签名绑定本人、内容范围、一次提交 ID 及可用的原聊天来源；确认 API 不接受 DSH 任务凭据。固定两种 DshSubmission 保存确认结果，实现刷新恢复与幂等，不再创建另一套评分引擎。

**Spec:** 完整规划和迁移表的诊断、人工升级业务，以及用户“继续”的授权。

## 约束

- 继续用 UniMind React 页面和服务器 harness，不运行旧自由写工具或自动发送通知。
- 保留 quiz.exam、faq.system 权限；题目只来自受管范围，不向模型或卡片泄露答案。提交只允许签名题目，答案从数据库读取。
- 首次诊断仅完成一次；已完成者引导原诊断页重新评估。诊断草稿有效 5 分钟，超时不自动提交；已成功结果可恢复。工单草稿 24 小时有效，必须明确确认发布。
- 提交记录唯一 ID，内容指纹冲突返回 409。模型不能调用确认 API；学生取消、失败或只看草稿均不产生业务写入。
- 工单正文可在确认前编辑；不携带附件、不增加教师通知或公开渠道。原聊天删除或未成功时不能确认它的草稿。
- 模型候选仍最多 8 个；新增 practice 内诊断能力和独立 support 组。
- 数据库迁移只在隔离临时数据库验收，不动真实 .env、不生产发布。

## 实施与验收

- 原业务工具保留，但 DSH run_diagnostic 仅允许 generate，不注册 submit；create_faq_ticket 只返回草稿。21 个已迁移工具分组提供，practice 含诊断后仍为 7 个业务工具加发现工具，support 独立提供人工答疑。
- 诊断签名绑定本次题集和本人，5 分钟内须明确提交；本次题目不可替换或重复，不接收模型提供的答案/知识点字段作为评分依据。确定性判分、Memorix 初始化和首次完成状态使用原服务，三者与 DshSubmission 同事务落库。已完成者使用原诊断页重新评估。
- FAQ 只有学生核对、可选编辑正文并点击确认发布后才创建；页面明确提示同学和老师可见。不生成附件或发送通知，不承诺回复时限。
- 新增 0032_dshsubmission，只增加确认事实表：唯一 request_id、本人、固定 kind、内容指纹、结果与时间。同一内容重复提交恢复原结果，内容改变返回 409。刷新通过本人结果接口恢复；正式业务结果不随聊天删除而丢失。
- 签名绑定当前内容范围和可用的原提问来源。原提问未成功或已删除时拒绝新增确认；模型任务凭据调用确认接口为 401。独立开发 Host 使用本人凭据准备的草稿没有站点提问来源，仍须本人明确确认。
- 三项确认聚合冒烟覆盖题集/答案权威、零草稿写入、跨用户、权限撤销、超时、来源、篡改、重复和冲突；与原只读/路由共 6 项通过。最终相关记忆和确认 10 项通过。
- 实际 SDK/ASGI 通过新增诊断卡、FAQ 草稿、手动确认、重放和结果读取，确认本身无新增模型调用。原正式聊天/标题/评分/删除与专注链路仍通过。临时数据库已执行 0032，makemigrations --check 无遗漏。
- 浏览器原小宇页实际完成 1/1 合成诊断、编辑答疑正文后发布，原 /qa 显示修改后的正文；返回小宇恢复诊断与答疑已提交结果，无重新落库或扣次。结果加载时隐藏待填写表单，避免把已发布内容短暂显示为“尚未发布”。截图 .m0-state/m0-diagnostic-confirmation-proof.png、m0-faq-confirmation-proof.png。
