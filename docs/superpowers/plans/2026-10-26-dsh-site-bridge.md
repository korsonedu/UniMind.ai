# DSH 站点身份与额度接入实施计划

> 使用 superpowers:executing-plans 连续执行，用户已要求继续直到完成。本计划只在隔离 worktree 实现与验收，不部署。

**Goal:** 学生通过现有 Django 身份调用服务端 DSH，同一轮复用既有 AI 额度预留、幂等与成功结算，不依赖开发 Host 的固定学生身份。

**Architecture:** Django 认证后签发短时、只允许 DSH 业务回调的任务凭据，在独立 Python 子进程中运行锁定 SDK。每个进程仅持有本轮学生凭据，按学生隔离原生状态；文件锁阻止同一学生并发修改状态。业务查询仍回到 Django。复用 AIUsageReservation 和 WeeklyAIUsage，不新增账本或数据库模型。

**Tech Stack:** Django/DRF、现有 Token/Cookie 认证、Django signing、现有配额服务、DSH SDK 0.2.1rc2、Linux/macOS 服务端文件锁。

**Spec:** 新 UniMind 完整规划 v1.2 的服务端 harness、统一接入、会话隔离和权益边界。

## Constraints

- 新站点运行入口默认关闭；原正式小宇入口不切流。
- 不创建长期学生 Token，不把站点或模型凭据交给模型或写入前端响应。
- 120 秒任务凭据只允许 dsh/context 和 dsh/tools；聊天回调还绑定当前 pending 额度预留及 attempt_id，结束即失效。
- 模型、Python 路径、回调 URL、状态目录均来自服务端设置；请求不能指定。回调只允许 loopback；官方模型来源仍固定 DeepSeek，模拟仅限 DEBUG 的显式本机配置。
- 每轮完整完成才确认既有额度，失败释放；重复 request_id 不再运行。只读会话操作不计 AI 额度。
- 文件锁保证单台服务器的同学生状态串行，不宣称跨节点调度或生产容量已经完成。

## Review Focus

- 伪造、过期、已完成任务及跨用户会话 ID 均不能扩大访问。
- 同 request_id 不重复扣费或调用，失败/超时/不完整回答释放预留。
- 同时两个学生不共享进程环境、原生会话、记忆和凭据；同一学生的并发修改返回忙碌。
- 服务端不公开配置/原始异常；子进程超时终止所属进程组，防止遗留运行时。
- 删除会话清除正文、原生状态及幂等缓存中的正文，保留既有用量事实。

## 实施判断与证据

- 站点 API 默认关闭，使用既有 Cookie/Token 身份；仅回调端安装 DSH 任务认证。没有为用户创建长期凭据，也没有改正式小宇入口。
- 原配置使用 SQLite，实际两个学生并发预留曾复现 database is locked。新入口通过单机文件锁串行化短额度写入；模型进程仍并发。每用户的父请求锁覆盖额度提交和删除，worker 同时保护原生状态，另有 4 个全局 SDK 槽位。此判断适用于当前单机阶段；代价是同一学生不能同时操作两个会话，不代表跨节点协调或生产吞吐完成。
- 实际站点链路已通过：两个学生并发运行独立 SDK 进程，模型请求中不混入另一个学生的记忆/临时代号；跨学生读取/删除返回 404；原生恢复保留前轮消息；重复 request_id 不增加模型请求；既有周额度最终为 [2,1]，模拟 422 失败释放额度；占满四槽位时调用模型前拒绝。
- 删除同时清理可见正文、原生状态和幂等缓存正文，保留用量及无正文删除标记；删除后旧请求返回 410。
- 一次独立复核发现两项 P2：超时绕过 worker 清理、删除缓存失败后无法重试。两个定向检查先失败，修复后通过。父进程现在原子分配新会话目录和 ID，终止整个进程组后可清理未交付的新会话；既有会话不删除。删除先提交无正文标记，再删除文件；仅当前用户有删除记录时允许缺失文件继续完成，其他账号仍 404。
- 4 项站点后端聚合冒烟、实际站点端到端验证通过。未新建模型、账本、数据库迁移或价格；没有访问付费模型，没有部署。

真实模型工具选择质量、费用金额上限、正式留存策略、生产恢复演练与公开上线未验收。主规划中的真实评分、内容建设与商业规则仍按后续阶段处理，不将本机协议成功当作完整产品发布。
