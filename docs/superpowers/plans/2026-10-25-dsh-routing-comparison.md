# DSH 工具候选路由对照记录

日期：2026 年 10 月 25 日。来源：隔离 Django 数据上的 test_dsh_routing_comparison，含 11 个合成代表问法和 1 个注册用户边界检查。

## 口径

旧路径使用现有 route_tools，显式令旧 LLM 分类返回 None，观察确定性回退；新路径复用同一候选策略，按当前权益筛目录并排除 Agent 笔记写入，再与 M0 已开放的 5 个只读工具求交集。未运行旧 LLM 对照，也没有验证实际 Embedding 召回质量。

这里检查必要工具是否进入候选，不报告模型选对率或实际任务完成率。8 个有明确工具要求的样例均命中必要候选；3 个边界样例未出现指定禁止工具；注册用户的候选及可执行工具均为空。8 个有工具需求的样例中，3 个所需工具全部在当前 M0 执行集合，另 5 个依赖尚未迁移工具，不能据此宣布完整小宇可用。

## 结论与未通过项

当前小目录策略通常保留 21 个只读候选，批改工作流补到 22 个；即使“你好”也保留 21 个，候选 Schema 约 16 KiB。它保住了必要工具，但没有实现精简候选预算。不能把本轮结果写成“准确缩到 5～8 个”。

当前实际向 DSH 提供的 5 个工具 Schema 为 3298 bytes。该差异来自执行迁移范围的限制，不能归因为 DSH 提升了路由效率，更不能用作正式成本下降结论。后续需测分组、按步候选与受限 DSH 意图分类，在不漏工具的前提下收敛预算。

纯问候样例检查未授权写工具不进入候选；它不证明模型一定不调用只读工具。M0 提示词已允许无需查询时直接回答，实际模型行为另做少量验证。

旧路径计时只覆盖 route_tools，新路径计时还包括权限、记忆数据库查询和上下文装配；不是同口径性能对照。下列毫秒数是单次本机记录，不据此判断吞吐或生产延迟。
