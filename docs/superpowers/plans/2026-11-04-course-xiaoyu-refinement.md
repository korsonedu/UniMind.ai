# 视频页小宇与课程发布实施计划

> 执行方式：本会话直接实施，使用 executing-plans；按用户要求只做必要冒烟，不新增完整测试体系，不提交或发布生产。

**Goal:** 落实用户对视频页评估第 1～5 项的确认，并将新课程发布控制放到 Directus 管理端。

**Architecture:** 保留当前 React 课程布局与聊天 Hook；复用现有可拖动分隔线、菜单和设计变量。Django 保存课程发布状态，Directus 管理草稿、转写、讲稿复核与主动发布，所有学生读取沿用统一课程可见性规则。

**Tech Stack:** React、TypeScript、Zustand、现有 Radix 控件；Django、Vue Directus 管理扩展。

**Spec:** `docs/audit/2026-11-04-video-xiaoyu-assessment.md`，以用户后续确认与修正为准。

## 约束与实现判断

- 不改变现有主站的色彩、字体、图标库、工作区结构，不增加依赖。
- 新课程默认草稿，转写完成且有有效讲稿后才允许主动发布；人工校对沿用现有讲稿编辑器，不自动发布。
- 已有课程迁移为已发布；替换视频回到草稿，避免新视频与旧讲稿错配。
- 后台管理员可管理草稿；学生列表、详情、媒体、搜索、离线授权遵循发布状态。
- 保留首次输入固定片段、原请求重试、账号隔离和引用快照验证。
- 拖动指右侧学习栏宽度调整，沿用现有分隔线并补齐顶部收起／展开入口；手机不提供桌面宽度拖动。
- 仅改必要文件；保留原有未跟踪文件；不自动提交、合并或部署。

## Review Focus

- 未发送草稿恢复后位置不漂移，缺位置的旧草稿须显式选段。
- 切换本课会话时问题、位置和恢复请求保持对应；通知定位确切会话。
- 发布前学生无法通过直链、文件或 AI 搜索读取草稿。
- 发布与替换视频、重新转写并发时不可留下已发布但讲稿错配的课程。
- 桌面拖动与顶部按钮一致；窄屏、大字、深色输入及公式保持可用。
