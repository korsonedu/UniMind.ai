# 科晟统一账号与学员权益设计

日期：2026 年 10 月 7 日。

状态：业务方向已确认，本文待审阅。尚未修改认证、权限或数据库，尚未上线。

## 目标与边界

官网面向全部学生，公开查询继续免登录。注册创建统一的科晟账号，登录用户可以收藏院校，注册本身不授予 UniMind 学习权益。

学生具有有效的 UniMind 学习权益时，首次进入学习平台自动加入科晟智慧机构，角色固定为学生。已有 UniMind 用户继续使用原用户 ID、密码与学习记录，不创建第二套账号。

学生、机构、课程及权益管理放在 UniMind 管理端。Directus 只维护官网内容与择校资料，不保存第二份用户密码、会员状态或服务授权。

本次设计拆成三个交付，依次实施：

1. 学员权益管理与自动加入机构。
2. 两端统一登录。
3. 官网院校收藏。

先审阅第一项的数据与权限规则，再形成对应实施计划。登录和收藏使用同一用户 ID，但不在第一项中假装已接通。暂不实现自动支付开通、多机构切换、营销自动化和咨询时携带筛选条件。

## 管理入口选择

推荐在 UniMind 现有管理界面增加“学员权益”，沿用全局用户与机构学员入口及现有管理角色。管理员无需在两个后台重复设置权限。

将学员权限放进 Directus 会引入与 Django 用户、机构、订单及权限检查之间的同步，删除或到期时还需要处理同步失败。当前不采用这条路径。

独立建设第三个账号和权限后台会增加部署与迁移，本阶段也不采用。

## 本地代码现状

以下为本地代码检查结果，生产数据和配置尚未核实：

- `users.User` 只有一个 `institution` 外键，当前无法表达同时属于两个机构。
- 注册用户默认 `is_member=False`、`personal_plan=free`，注册流程未自动加入机构。
- `users/views_institution.py` 的加入流程会同时设置 `is_member=True` 和机构套餐对应的会员等级。
- `users/services/membership.py` 的 `activate_membership()` 会在部分条件下修改用户所属机构的套餐和到期时间。个人支付、激活码与机构订阅流程均存在对此函数的调用。
- `users/permissions.py` 的 `get_user_capabilities()` 默认给所有已登录用户 `learning.access`；会员权限与部分功能权限采用不同判断路径。
- 课程列表与详情主要使用 `IsMember` 加机构隔离。当前检查无法独立表达某学生只购买某个课程包。
- `UserAccessProfile` 和权限组已经存在，可用于管理操作权限，但没有完整的按服务记录有效期、课程范围及开通来源的模型。
- UniMind 已有机构套餐、订单和机构订阅；学生服务权益不能直接复用机构订阅记录。

## 第一项：权益数据

增加两个明确职责的模型，放在现有 `users` 应用内，不另建通用权限平台。

### 服务包

每个服务包属于一个机构，具有机构内唯一编码、显示名称、服务类别及启用状态。类别区分 UniMind 学习服务和择校咨询服务。

学习包显式配置允许的功能，以及允许的课程专辑范围。没有配置课程范围时，不默认开放全部课程。全部课程仅通过管理员显式选择的“全部课程”范围开放。

咨询包只表达已开通的服务及有效期，不授予学习权限。服务价格、咨询交付次数和周期不由本次代码预设。

停用服务包只停止新的开通，已授予权益继续按原快照和期限执行；批量撤销既有权益需另行确认。专辑被删除或移出对应机构后，不因为原范围失效而回退为全部课程。

### 学员权益记录

记录用户、机构、所选服务包、开始时间、结束时间、状态、授权范围快照、开通来源、操作人和备注。结束时间为空仅允许管理员显式选择长期有效。

状态为有效、暂停或已撤销。是否已到期由服务端当前时间判断，不依赖每天一次的定时任务。有效区间为开始时间已到且结束时间未到。

每次开通保存服务包范围快照，后续修改服务包不静默扩大已有学生的授权。暂停、恢复、撤销和调整期限写入现有机构审计记录，不物理删除权益历史。

同一学生可以具有多条服务权益；实际可用范围是仍有效的学习权益的并集，并受机构功能和额度上限约束。咨询权益不进入这个并集。

标签、注册来源、机构归属和一个 `is_member` 标记都不能单独作为付费证明。未来支付开通调用统一的学生权益服务，现阶段由管理员人工开通。

旧会员字段在过渡期只用于兼容已核对的旧流程。新科晟权益由权益记录判断，不能由旧标记反向生成授权，也不能由每日旧会员降级任务删除独立服务权益。

## 第一项：自动加入科晟智慧

目标机构使用服务端配置的固定机构 ID，并检查机构存在、启用且套餐有效。不能根据用户提交的机构名称、角色或邀请码自动授予权益。

学生首次进入 UniMind 的服务端入口按照以下规则处理：

| 条件 | 结果 |
| --- | --- |
| 未登录、账号停用 | 不进入学习平台 |
| 没有已开始且未到期的学习权益 | 提示尚未开通，不加入机构 |
| 有科晟学习权益，无所属机构 | 检查容量后自动加入，固定学生角色 |
| 已属于科晟智慧 | 保持原归属和角色，重复请求不延长权益 |
| 已属于其他机构 | 返回明确的机构冲突，保留原机构，由管理员处理 |
| 机构停用、套餐到期或容量不足 | 不自动加入，提示联系管理员 |

加入操作在数据库事务中锁定用户和目标机构，再检查归属、容量及有效权益。并发请求只加入一次，只写一次加入审计，不创建重复账号或重复权益。

官网新注册用户首次加入固定为学生，不能通过注册或加入接口变成教师、负责人或平台管理员。既有教师和负责人登录保持原角色，不因入口经过官网被降为学生。

到期、暂停或撤销后停止对应学习权限，保留机构归属、账号和历史学习记录。保留归属仍计入现有机构学员数，本阶段不改变机构容量计算。

## 第一项：权限执行与管理操作

保持现有平台管理员、机构负责人、教师和学生四层角色。新增的付费权益判断与角色检查、机构隔离分别执行，不让学习权益授予管理权限。

- 平台管理员可以管理科晟服务包、查找统一账号并开通权益。
- 科晟机构负责人可以管理本机构服务包和学生权益，可以通过已验证邮箱准确查找待开通账号，不开放全站用户列表。
- 普通教师默认可以查看本机构教学需要的学员信息，不能开通、延长或撤销付费权益。
- 学生仅能查询自己的服务状态，不能修改权益、角色或机构。

管理界面显示“所选服务包、授权范围、有效期、状态、开通来源、操作人及历史”，开通前展示确认信息。查找官网未入机构账号不自动使其加入，首次实际进入 UniMind 时才完成加入。

课程列表只列允许的专辑，课程详情、播放授权、课件、字幕和大纲分别校验实际资源是否属于授权范围。仅过滤列表不足以阻止直接请求其他课程 ID 或文件。

付费文件必须经过鉴权下载或私有存储的短时授权链接。撤销后立即阻止新的授权请求，但无法收回已下载文件，已签发链接也可能在短时有效期内继续可用。若现有存储或 CDN 公开暴露付费文件，须先处理这一出口才能宣称课程隔离完整生效。

AI、题库和其他付费学习功能在后端检查学习权益与功能范围；WebSocket 和持续会话也要处理权益撤销及到期。公开资料、登录注册、个人账号设置和官网收藏不受付费学习权限限制。

前端入口读取后端返回的有效权限，不自行根据 `is_member`、机构名称或本地存储推断权限。后端每次访问检查状态，授权变更后清理相关缓存，不能只等下一次登录生效。“立即生效”指新的受保护请求，已下载文件及已签发链接的限制见上一段。

## 第一项：旧系统和支付边界

第一阶段将新权益规则用于科晟接入及科晟机构学员，其他机构现有业务保持原样。不得直接全局替换会员判断后让其他机构学生失去服务。

旧科晟学员上线前先生成只读核对报告，列出机构、角色、现有会员来源、到期时间及课程范围依据。核实后才能建立旧权益记录，不能把所有 `is_member=True` 都判定为已付费，也不能无依据缩小旧课程范围。

管理员确认的旧有效权益按原期限保留，长期权益保留长期设置；教师、负责人和平台管理员保持原管理权限。旧范围尚无法确认时，不启用生产切换，不靠默认“全开放”或“全关闭”完成迁移。

机构套餐购买与学生服务购买使用不同的处理入口。对现有 `activate_membership()` 的改造必须同时核对个人订单、激活码和机构订阅调用点，保留机构正常续订。学生开通服务不得修改全机构套餐及到期时间。

科晟公开邀请码和按机构 slug 加入的旧入口不能绕过学习权益检查。其他机构邀请流程不在本阶段无条件收紧。既有批量默认机构分配命令不用于官网注册学生。

所有数据库结构变更追加 migration，不重建旧 migration，不删除账号、机构、订单、权益或学习数据。不在生产数据库上执行未经确认的迁移或批量变更。

## 第二项：统一登录衔接

账号品牌使用“科晟账号”，免费学生可在官网完成注册、登录、找回密码和账号管理，无需看到 UniMind 学习首页。

共用现有用户 ID，两个域名分别维护自己的有效会话。后续使用成熟实现提供授权码单点登录，校验客户端、固定回调地址、state 和 PKCE，授权码短时且只能消费一次。

官网会话只服务官网身份与收藏，不把 UniMind 长期 Token 放进 URL 或浏览器 localStorage。有效 UniMind 会话可在短暂顶层跳转后返回官网；官网有效会话进入有权使用的 UniMind 也无需重复输入密码。

统一账号认证不要求学习权益，进入学习资源才检查权益。官网退出和全部服务退出分别处理，密码变更与账号停用使相关会话失效。不能通过重复调用当前普通登录接口轮换 Token，把用户另一端会话顶掉。

此项单独形成实施计划，认证实现和生产域名配置未确认前不声明已支持单点登录。

## 第三项：官网收藏

按统一用户 ID 与稳定院校项目编号保存收藏，建立唯一约束。只允许本人读写自己的记录；登录后返回原页并恢复待完成的收藏操作。

收藏免费开放给登录用户，不开通学习权益，不触发机构加入。写请求检查 CSRF、请求来源和项目有效性，公开查询保持静态发布。

## 第一项验收与切换

仅做与账号、权益和机构变更直接相关的验证，不运行整站反复回归，不新增临时测试页面。权限隔离涉及付费资源，必须有针对性的自动检查。

验收覆盖：无权益不能加入；有效权益首次加入；重复和并发加入；其他机构冲突不覆盖；容量与机构状态；开始时间和到期边界；暂停和撤销立即生效；咨询权益不能访问学习资源；不同服务包不能互读课程与文件；学生和教师不能自行开通权益；个人开通不改变机构套餐；旧学员及其他机构权限保持。

生产切换前必须确认科晟智慧的实际机构 ID、机构套餐与容量、旧权益核对报告、迁移前数据库备份及回退路径。开发过程可以使用隔离测试数据，不能替换用户现有开发数据库。

代码只在现有 main 上修改，保留当前所有用户改动，不创建工作树或功能分支。每次交付分别报告已改代码、本地验证、未执行的数据迁移和未部署事项。

## 第一项涉及的现有模块

- `backend/users/models.py`：追加服务包和学生权益模型。
- `backend/users/services/`：权益开通、撤销、范围判断及自动加入事务。
- `backend/users/permissions.py`：复用角色 helper，集中接入权益检查。
- `backend/users/views_institution.py` 与新增权益接口：科晟加入入口与机构内管理范围。
- `backend/users/urls.py`：注册权益与自动加入接口。
- `backend/users/services/membership.py` 及支付、激活码调用点：区分个人与机构套餐操作。
- `backend/courses/` 及付费学习接口：课程范围、功能与资源权限。
- `frontend/src/pages/InstitutionStudents.tsx` 与学习入口：沿用管理布局，增加权益操作和服务端状态展示。

实际文件拆分、接口签名和验证命令在本设计确认后的实施计划中确定，不在本文件预先生成实现代码。
