# 学生功能权限与课程分类调整

本次按用户明确指定的业务边界实施，不新增教师端，不编造教师的模块清单，不删除尚未决定去留的知识点。

1. 课程目录采用“学科 → 模块 → 视频”。学科存为模块的独立标签，同学科内模块名唯一。新模块需要填写学科，旧模块仅在历史数据无歧义时回填；未能确定的内容保留待归类状态。旧课程可临时显示已有知识点对应的学科，但课程列表与播放不等待知识点接口成功。
2. 专辑和知识点移出当前管理后台的课程上传表单，历史字段、数据与其他用途保留。分类字段、模块公开标记、学习服务关联模块均不参与功能授权。
3. 功能权限复用用户访问档案，由 Directus 中的“学员 → 查看服务 → 配置权限”维护。配置项为小宇、学习记录、课程中心、习题训练、课程答疑、自习室。默认沿用现有开放行为，不批量关闭现有用户或调整注册策略。
4. 侧栏保持入口可见，未开通项禁用；直接访问 URL 仍会被拦截，提示联系管理员。后端 API、课程媒体、自习室 WebSocket 读取同一用户授权。服务包只保留既有 AI 额度及有效期职责，不代替功能权限。
5. 两个管理员的管理权限与学习功能授权分离，配置学生功能不会修改账号角色。权限保存与审计共同提交，不丢弃未知历史权限项。

验证范围：原有三项后台定向检查，加上逐用户课程/媒体权限及学科/上传校验，共五项；两端类型检查与构建、有限的桌面及移动端视觉核对。没有整套回归，没有真实学员账号测试，没有生产部署。
