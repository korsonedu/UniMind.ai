# Directus 统一入口与 UniMind 业务管理设计

日期：2026-10-15

## 1. 目标与边界

在官网现有 Directus 中增加“UniMind 管理”专区，取代日常使用原生 Django Admin 的操作方式。UniMind 前台继续保持 student-native，所有角色使用相同的学习界面。

两位管理员分别登录，权责相同，操作记录能够区分人员。复用官网登录入口，保留 Django 对学习平台数据、业务规则和权限的控制。

本设计不合并数据库，不在 Directus 建立学员或订单副本，不恢复教师工作台，不更改官网文章与院校资料的发布流程。

当前 `backend/courses/access.py` 的未提交改动将模块视为分类打标，学习权益不参与课程可见性判断。本项目保留该逻辑，课程准入模型另行讨论；服务包关联模块不能被界面描述为已实现的课程访问限制。

## 2. 已确认的现状

- 官网部署配置固定为 Directus 12.4.1，现有后台维护官网内容。
- Directus 容器目前配置 512 MB 内存，不能让课程大文件经该进程整体缓冲。
- UniMind 使用 Django、DRF、Redis 和既有 OSS 分片上传，已有模块批量归类、服务包配置、个人权益发放与撤销逻辑。
- 学生课程 GET 接口按学习侧规则查询，不能作为完整管理列表复用。
- 原生 Django Admin 保留为开发运维兜底，业务迁移完成前不删除。
- 本轮仅设计，不安装扩展、不创建账号、不改生产配置。

## 3. 分期交付

第一期完成两条可日常使用的完整流程：课程与模块管理、学员与服务权益管理。

第一期导航只显示已实现的三个区域：课程与模块、学员与权益、操作记录。进入专区默认打开课程列表，不增加独立统计大屏。

后续阶段迁移题库与知识目录、订单只读查询、AI 配置和通知。每个阶段完成后再切换对应日常入口，不将第一期交付称为全部后台迁移完成。

## 4. 系统职责

| 部分 | 职责 |
| --- | --- |
| Directus 管理页面扩展 | Vue 3 页面，沿用 Directus 导航、组件和登录状态 |
| Directus 服务端扩展 | 验证操作者，限定可调用的业务操作，向 Django 签发短时请求 |
| Django `/api/backoffice/` | 管理查询、业务校验、事务执行、操作审计 |
| UniMind 既有业务服务 | 课程归类、文件校验、服务快照、有效期和权益撤销 |

扩展源代码放在 UniMind 仓库的 `admin-extension/`，与 Django 接口一起版本化。构建产物按 Directus 扩展格式交付；不把管理扩展加入 UniMind 学习端构建。

官网仓库只在部署阶段调整扩展挂载和服务端环境配置。不得将扩展修改混入官网内容数据或自动触发内容迁移。

## 5. 登录、权限与两位管理员

管理员继续在官网 Directus 登录，不要求在管理页面输入第二套密码。

Directus 服务端必须验证当前会话有效且具备管理权限。服务端配置显式的操作者名单，与 Django 配置保持一致；名单包含两位管理员各自的 Directus 用户 UUID。

Django 使用服务端配置，将每个 Directus UUID 映射到独立、已启用的 Django 管理账号。映射到的账号必须具备同一等级的完整后台管理权限。仅凭同名或相同邮箱不得自动提权，也不在请求过程中自动创建管理员。

未映射账号、已停用账号及普通学员均拒绝访问。两位管理员拥有相同功能，不划分主账号与次账号。实际账号标识在接入配置时核对，未经确认不删除或停用历史账号。

浏览器只请求 Directus 同源的业务入口。Directus 到 Django 的请求包含操作者 UUID、时间戳、随机 nonce，以及绑定 HTTP 方法、路径、查询参数和请求体摘要的 HMAC 签名。Django 校验时效、签名、映射和防重放记录，认证缓存不可用时拒绝管理操作。

桥接密钥仅保存在两端服务环境中，不发给浏览器，不进入源码或构建产物。该认证方式仅用于专用后台路由，不放宽学生接口的认证。

Directus 服务端采用固定 Django 地址和操作白名单，禁止浏览器指定任意目标 URL、路径或转发认证头。

## 6. 课程与模块

课程页提供搜索、模块筛选、待归类筛选、稳定分页、编辑和多选批量归类。列表展示标题、模块、视频或资料状态及更新时间。

模块页维护名称、简介、排序和既有免费开放字段；保留该字段的数据，不宣称当前可见性已经依据该字段生效。不代教师编造模块清单。

新课程必须选择模块。课程归属由所选模块确定，关联专辑和知识点必须属于同一内部教学机构。既有课程不因后台上线而改变归属。部署配置指定新增模块的内容归属，未配置时禁止创建并给出明确提示；界面不暴露 B 端机构套餐或自助建租户流程。

批量归类必须校验全部课程和目标模块，失败时不部分提交。移除非空模块须先迁移课程；删除课程需要明确确认，受引用保护的内容返回可处理的原因。

视频沿用 OSS 分片直传，浏览器取得签名后向 OSS 上传。Directus 只转发上传初始化、续签和完成等小型控制请求，不能缓冲整段视频。上传对象须由 Django 绑定到本次操作和内容归属，完成前校验对象身份与类型，不能接受任意外部文件地址。

课件和封面沿用 Django 文件校验与存储。小文件上传采用受限的专用操作，不实现任意文件代理。

## 7. 学员与服务权益

通过邮箱或账号搜索学员，结果只返回后台操作所需资料。选中后展示当前服务、有效期、月度 AI 对话使用量和权益来源。

服务配置维护名称、说明、以元显示的价格、有效天数、月度 AI 额度及关联模块。价格在接口边界转换为整数分。沿用现有上架价格与有效期校验，不预置虚构产品。

发放流程为选择学员、选择服务、选择“课程配套”或“管理员赠送”、确认。调用现有 `grant_product()` 生成快照与有效期，服务包未来编辑不回写历史快照。

发放请求提供幂等标识，双击或网络重试不得重复赠送或顺延。已有订单权益按原订单规则处理，不能从赠送界面伪造支付来源。

撤销需要确认，只改变选中权益的撤销状态，不删除历史记录。月额度取最高值、同一服务续期规则沿用现有业务函数，不在 Directus 重写。

## 8. 接口与审计

新增专用后台路由分别承接课程、模块、上传控制、学员查询、服务包、发放和撤销、操作记录。共享已有序列化校验与业务函数，不通过临时修改 `request.user.institution` 模拟管理身份。

管理查询可读取受管范围内全部内容，学习端查询规则保持不变。批量操作、权益发放及其成功审计在 Django 事务内完成；记录操作者、操作类型、目标 ID、结果与请求标识。

复用 `core.SecurityAuditLog` 的 `admin_action` 事件，不记录密码、密钥、完整请求体或学员对话。审计保存真实映射账号，不能把两人的操作统一记到一个系统账号。

列表读取不触发内容变更。接口统一返回可展示的错误与请求标识；页面提交失败保留输入，不自动重发写请求。无权限、配置缺失、业务冲突和服务不可用分别提示，不展示服务端堆栈。

## 9. 有限验证与切换

只执行扩展类型检查与构建、Django 检查，以及身份拒绝、模块归属校验、发放幂等三处聚焦检查。不使用真实学员账号做整套回归，不在生产发送测试通知或制造订单。

本地使用隔离的 Directus 扩展挂载，不读取或修改官网生产数据库。预览环境完成一条课程归类和一条服务发放流程，才确认第一期可用。

生产切换另行取得发布授权，并在切换前核对两个操作者映射、服务端密钥、内容归属、扩展版本与官网备份。完成备份后挂载扩展并启用入口，不进行学习数据迁移。

移除扩展挂载并重启 Directus 即可撤回新入口，Django 数据与官网内容保持原位。关闭新入口不会删除课程、服务权益或审计记录。

## 10. 验收口径

- 官网原有内容后台继续工作，学习端不出现管理入口。
- 两位指定管理员均可完成同样的课程归类和权益发放操作，记录分别可追溯。
- 普通用户、伪造身份、过期或重复桥接请求被拒绝。
- 课程与模块不跨内部归属错误关联，模块分类不被暗中恢复为课程准入条件。
- 重复提交一次赠送操作只产生一份权益，撤销后记录仍可查。
- 扩展构建和本地可用、账号接入、生产发布分别报告，不互相替代。
