# UniMind 科晟课程交付平台调整设计

日期：2026-10-18。

状态：用户已逐项确认业务方向，并于 2026-10-18 授权“开始做吧”。本地实现已按本文推进，未推送、执行生产迁移或部署。第 10 节未收到具体业务参数的事项保留为待配置；实现状态与边界见文末。

## 1. 产品定位与范围

UniMind 服务科晟课程交付，不再经营面向其他机构的 B 端 SaaS。课程收费在线下完成，不在 UniMind 销售课程。非课程学员可有限使用小宇，未来再开放公开课；公开课不属于本次交付。

保留 AI 加量购买。AI 加量不能授予课程访问权、改变课程学员状态或获得后台权限。

用户要求先决策再实施，本阶段交付设计与迁移清单。实现仍沿用现有 Django、React 学习端与 Directus 管理扩展，不另建后台或权限平台。

## 2. 已确认决策

| 事项 | 已确认规则 |
| --- | --- |
| 管理入口 | 教学生产功能集中迁入 Directus，UniMind 一级功能在侧栏切换 |
| 迁移范围 | 现有教师能力全部迁入，完成后再决定哪些保留，不只迁出题 |
| AI 与 tools | 页面表达教学任务，tools 作为内部执行能力，AI 配置置于后台 |
| 身份 | 只有学生和两名管理员；不设计独立教师权限体系 |
| 学员分类 | 普通学生区分课程学员与非课程学员，由管理员手动调整 |
| 服务页面 | Billing 改为“我的服务”，展示身份、服务、用量及实际购买记录 |
| 在线销售 | 保留 AI 加量；停止课程销售和机构套餐销售 |
| 激活码 | 取消激活码功能，采用管理员手动调整学员分类 |
| 使用周期 | 基础 AI 额度每周恢复 |
| 体验功能 | 非课程学员先限定小宇问答，后续再开放公开课 |
| 额度差异 | 课程学员额度高于非课程学员；课程使用不消耗 AI 问答额度 |
| 额度结构 | 每人一个统一的问答额度口径，不按课程或服务包设置多份额度 |
| 学员退出 | 回到体验额度，服务范围等同非课程学员 |
| 管理员使用 | 原教师生产功能由两名管理员使用，管理员 AI 不限量 |
| 计次 | 用户接受以问答次数表达用量；失败、取消及同次请求的重复重试不计次 |
| 多租户 | 目标改为科晟单平台，先退出 B 端产品能力，再解除机构依赖 |
| 验证 | 最小修改，针对变更做冒烟检查，不做整站反复回归 |

课程学员与非课程学员是同一学生身份下的服务状态，不增加管理角色。两名管理员沿用各自账号和审计身份，不共用操作人。

## 3. 当前代码事实

- 学习端 `frontend/src/App.tsx` 已把工作台及多项旧管理路由重定向；`backend/ai_assistant/views.py` 排除并拒绝 `exam_generator`。恢复工作台需要管理入口和后端身份接入共同完成。
- `admin-extension/` 已管理课程、模块、题库、知识目录、学员、学习服务和操作记录，目前一级导航仍是顶部切换。
- `backend/backoffice/views.py` 与 `admin-extension/src/bridge.ts` 使用固定操作白名单；当前没有 AI 工作台的完整操作接口。
- Directus 桥接只允许两名指定管理员，并映射为两个独立 Django 管理账号。保持现有登录与服务端身份校验。
- `backend/users/learning.py` 当前按月记录使用，聊天入口先预扣次数；服务包通过最高月额度提供权益，尚不等于购买固定额外次数。
- `Pricing.tsx`、`Billing.tsx`、`Checkout.tsx` 仍表达课程模块、月度额度、激活码和学习服务购买，需要一起调整。
- `institution` 仍参与内容查询、管理身份、AI 工具许可、配额和 Memorix 配置，不能直接清空字段或删除过滤。

上述均为本地源码检查，不能据此宣称生产已具备或已取消这些行为。

## 4. 后台迁移范围

### 4.1 工作台现有工具清单

以 `backend/ai_engine/tools.py` 的实际工具注册和 `backend/ai_assistant/services/exam_generator_tool_executor.py` 为依据，逐项迁移并记录结果：

| 能力 | 后台交付 |
| --- | --- |
| `search_knowledge` | 查找知识目录与考点，作为命题上下文 |
| `quick_generate` | 按考点、题型、难度、数量快速生成题目 |
| 前端确认入库操作 | 查看并选择待入库题目，人工确认后入库；不把历史保存 handler 重新暴露为模型可自主执行的工具 |
| `launch_arc_pipeline` | 启动既有精修管线 |
| `check_pipeline_status` | 查询任务进度、状态及结果 |
| `get_workbench_stats` | 查看既有题库与工作台统计 |
| `get_student_detail` | 查询学员学习情况 |
| `send_notification` | 预览接收人及内容，确认后发送通知 |
| `list_courses` | 浏览现有课程资产 |
| `list_questions` | 浏览并定位正式题库 |
| `list_articles` | 浏览现有文章资产 |
| `render_visual` | 展示结构化数据、学情卡片和人工确认卡片 |
| `generate_student_report` | 生成并查看既有学情报告 |

同时迁移工作台对话历史、生成结果恢复、题目预览与选择、现有批量初始化入口、精修进度和已有工作台概览能力。既有内容管线的任务列表、详情、审核、重试与指标列入管理迁移清单，不因入口迁移丢失操作能力。

对话式操作和列表表单共享 Django 业务逻辑。迁移不等于复制一套生成器或建立第二份题库。生成结果保持待审核，题目入库和通知发送仍由管理员明确确认。

“全部迁入”指现有教学生产能力。已明确取消的激活码、机构开户和套餐销售不重新恢复。旧机构邀请能力须核对历史用途并登记退出结果，不允许通过邀请重新建立教师、机构所有者等身份。不得因旧页面文件存在而把题库交易市场、外部 API 销售等另行扩入本项目。

### 4.2 统一导航与操作

建议侧栏分组如下，分组名称和页面归属属于本稿提出的实现选择：

- 教学：教学工作台、题库、知识目录、内容任务。
- 内容：课程、模块，以及迁入能力确实需要的文章或资料入口。
- 学员与服务：学员、AI 加量商品、订单查询。
- 系统：AI 配置、通知及现有通知配置、操作记录。

一级导航具备独立地址，支持刷新与浏览器前进后退。已迁入的课程、题库等页面沿用现有后台；不再创建一套同用途页面。

统一页面标题、工具栏、搜索提交、筛选后回到第一页、分页、批量选择范围、表单操作区、保存反馈、错误和空状态。知识目录保留树形层级操作，聊天和管线保留其任务交互。提交失败保留输入；有修改的表单切换页面前提示；破坏性操作先确认；加载中阻止重复提交。

样式沿用 Directus 所处后台的整体层次，共用既有管理扩展样式，避免每页另设颜色、按钮和弹窗规则。不对学习端进行无关视觉重做。

## 5. 学员分类与学习范围

管理员在学员详情中手动设置课程学员或非课程学员，变更写入审计。停用账号、后台身份与学员分类分别判断，切换分类不改变管理权限。

非课程学员当前仅开放小宇问答及该体验所需的本人会话历史、账号设置、我的服务和 AI 加量购买。购买加量不开放诊断、练习、课程检索、课件、学情工具或课程内部资料。公开课留到后续明确内容与访问范围后实现。

课程学员保留课程交付所需学习能力和管理员现有功能开关。是否能看某资源由功能授权与资源访问控制决定，不能依据 AI 余额判断。视频、资料等普通课程访问不扣问答次数；已经属于小宇问答请求的课程内容讲解仍按一次问答计次，这是对“课程不耗额度”的本稿解释，需在文档审阅时核对。

从课程学员调整为非课程学员后，后续请求采用非课程学员的服务范围与基础额度，保留账号、个人学习记录和本人历史会话，不继续取得原课程资源的新访问授权。已下载文件和已签发链接仍受原机制限制，不能承诺收回。

本稿建议切换分类时保留当周已用次数，按新基础额度计算可用量，最低为零；不通过反复切换身份重新发放整周次数。该条属于实现建议，尚非用户原话。

## 6. AI 次数与计费

### 6.1 基础额度

每人一个统一的问答使用口径，课程学员和非课程学员分别配置基础周额度，前者高于后者。实际数值未获确认，不沿用月额度作为默认周额度。

本稿建议自然周按 Asia/Shanghai 周一 00:00 恢复，未用基础次数不累计，下次恢复时间明确展示；这是实现建议，尚未逐项确认。时间判断由服务端负责，不依赖用户本机时间或定时任务准点执行。

额度用完后展示等待恢复和联系我们。AI 加量入口继续存在，不强迫用户购买，也不暗示购买可以取得课程学员身份。

两名管理员不受问答次数上限约束，但继续记录实际 AI 消耗和任务状态。不限量不改变现有并发控制或请求限制。

### 6.2 成功与计次

一次用户提问获得完整成功答复计一次，内部模型轮次、工具调用和自动重试不分别计次。失败或取消不扣次数；同一请求重传不重复扣次数。用户主动提出的新问题并成功答复，仍是新的一次问答。

实现时须把现有入口直接预扣改为可完成或释放的使用预留：先保证并发不会超用，成功后确认消耗，失败与取消释放；同一请求仅有一个最终扣次结果。覆盖现有 HTTP、流式及 WebSocket 入口，不在不同传输路径各计一次。

内部将体验用户、课程学员和管理员生产任务的实际模型用量分别统计。失败不向用户扣次不代表供应商成本为零。

### 6.3 AI 加量

已确认保留在线 AI 加量购买。具体加量有效期、每包次数和价格尚未确认。

建议采用一次性次数包：基础额度优先使用，基础用完再消耗加量余额；加量余额不随周恢复清零。页面可统一展示总可用问答次数，并给出必要的来源明细，避免误导用户认为额外次数每周会再次发放。本条是待确认建议，不得直接执行。

若用户选择当周有效，则必须在商品和结算时写明有效时间。两种规则只能采用一种明确合同口径，不同时实现多个可配置商业模式。

支付成功按订单幂等增加已购买次数，不修改课程状态。使用原有支付和订单体系，移除新课程订单、机构订阅与激活码的有效入口；历史订单、支付回调核对和权益数据保留，待核对后制定兼容处理，不按新商品含义覆盖旧快照。

## 7. “我的服务”页面

展示当前课程学员或体验状态、本周基础额度、已用次数、剩余次数、下次恢复时间、可用加量信息，以及 AI 加量购买和真实订单查询。

删除课程在线购买、课程模块售卖、机构方案升级和激活码输入流程。管理员后台不再通过售卖课程服务包决定学生身份；由学员管理直接切换分类。课程线下收费不生成虚构的 UniMind 已支付订单。

“学习服务”旧页面需按新职责收敛为学员状态和 AI 加量商品管理，不能仅改名称而继续按旧服务包控制月度额度。

## 8. 退出多租户

先停止新机构注册、机构切换、机构套餐购买、席位销售、子机构及租户品牌等 B 端入口，再逐项解除机构依赖。科晟单一内容归属可临时作为兼容层，不以保留未来 B 端可能性为理由长期维护多租户逻辑。

迁移映射至少覆盖：

| 当前职责 | 单平台目标 |
| --- | --- |
| 机构所有者和教师角色 | 两名指定管理员的管理身份 |
| 机构套餐决定工具 | 学员服务状态、明确功能授权和管理员能力 |
| 机构内容归属与筛选 | 科晟内容及学习资源访问规则 |
| 机构月度 AI 配额 | 个人周额度、AI 加量与管理员不限量 |
| 机构资源上限 | 科晟内部容量与运行约束，不再做套餐升级提示 |
| 机构 Memorix 参数 | 科晟平台参数，保留既有学习与演化状态 |
| 机构配置与学情范围 | 平台配置及真实用户、课程、学员分组范围 |

先盘点所有历史机构和关联数据，再确定归并或保留方案。不假定数据库只存在科晟，不跨账号合并学习历史，不直接把所有内容改成公开。不能用清空 `institution` 或移除过滤替代权限迁移。迁移追加文件，不删除或重建旧 migration。

## 9. 分段实施与验收

本项目涉及多个模块，建议分段交付，每段完成可核对的业务流程后再推进：

1. 固定已确认业务规则，核对两名管理员映射、现有学员状态和旧数据来源。
2. 完成侧栏与后台统一交互，迁入全部现有教学生产能力并按第 4 节逐项登记结果。
3. 完成学员手动分类、非学员仅问答、周额度及成功计次。
4. 完成我的服务与 AI 加量，退出课程在线支付和激活码。
5. 解除多租户依赖，核对历史数据后清理废弃结构和文档。

此顺序为建议，不表示已开始实现。尚未确认的商业参数不得进入生产；可独立推进已确认范围的设计和实现计划。

实施时只做必要的类型与构建检查和定向冒烟：后台入口与两名操作者审计；生成审核入库与通知确认；非学员直接请求课程和工具被拒绝；周边界及并发额度；失败、取消和重试计次；加量支付幂等。使用隔离数据，不用真实账号造订单或发测试通知。

本地构建、迁移、账号接入和生产部署分别报告。发布和生产数据迁移需在具体方案完成后按用户授权执行，本稿不触发任何部署。
