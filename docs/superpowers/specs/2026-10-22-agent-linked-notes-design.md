# 个人笔记与 Agent 只读关联

日期：2026-10-22。状态：用户已确认书面设计，进入实现。

## 目的与已确认约束

用户要在 UniMind 中正常记笔记，并拥有类似 Notion / Obsidian 的组织能力。重点是两种 Agent 关联同时存在：记笔记时围绕当前内容讨论，以及让指定 Agent 长期参考指定笔记或笔记本。

用户明确“不希望 agent 修改笔记”，并确认以下边界：笔记由用户自己编辑；Agent 只能读取，不能创建、修改、删除笔记，不能移动目录或调整标签。讨论结果留在对话里，需要收入笔记时由用户手动摘录。

首版交付：笔记编辑与自动保存、多级笔记本、标签、收藏、搜索、双向链接、回收站、Markdown 导出，以及 Agent 临时参考、长期关联与来源引用。

以下为实现建议，不冒充用户明确作出的选择：首版笔记按个人私有处理；使用现有 React / Django / Tiptap；不依赖向量模型服务；优先接入学生端现有小宇 Agent，其他 Agent 复用同一关联模型并继续服从现有可用性与权限规则。

## 使用过程

### 写笔记与整理

独立入口 `/notes`，单篇入口 `/notes/:id`。主区域写笔记，目录区整理笔记本，Agent 讨论按需展开。移动端通过切换视图保留完整编辑区域，不强塞三列。具体排版在实现时沿用现有产品样式，以文字、留白和轻背景建立层次。

- 笔记可无所属笔记本，归入“未分类”；有所属时只放入一个笔记本。
- 笔记本可嵌套，支持新建、重命名和移动；移动不能构成循环。
- 标签跨笔记本使用；收藏和最近修改是快捷入口。
- 搜索覆盖标题和正文，可按笔记本、标签、收藏及关联 Agent 筛选。首版筛选即时使用，不做保存视图。
- 编辑支持标题、段落、列表、引用、代码、链接与数学公式。现有编辑器没有的能力只为笔记补齐，避免影响后台文章编辑。
- 用户输入 `[[` 搜索已有笔记并插入内部链接；链接以稳定 ID 为目标，改标题和移动后仍可打开。被引用笔记显示反向链接。首版不因输入不存在的名字自动新建笔记。
- 重名笔记允许存在，选择链接时用笔记本路径区分。

删除笔记先进入回收站，用户可恢复或永久删除。删除笔记本时，将其中笔记及子笔记本移至上级，再删除这个空笔记本，界面先明确这项行为。首版不实现笔记本子树的级联回收协议。

导出单篇或选定笔记本中的笔记为 Markdown，笔记本导出为 ZIP；保留目录、标签和内部链接，使用稳定 ID 避免同名覆盖，内部链接转换为导出文件间的相对路径。首版不做 Notion / Obsidian 全量导入，不做二进制附件上传。

### 围绕当前笔记讨论

在笔记中展开小宇时，明确显示“本次参考：当前笔记”。用户可选择一段文字作为本次提问的重点，也可添加其他笔记或移除参考项。只有真正发送问题时才读取内容。

“本次参考”属于当前用户、Agent、会话的组合，在该会话内持续有效，直到用户移除；新建会话不继承，切换会话恢复该会话自己的参考列表。选中文字属于单次问题，不默认变成长久附件。

每次发送前保存当前笔记，成功后引用该版本；保存失败则保留问题与草稿，明确失败并允许重试，不悄悄发送旧版本。已有会话中从笔记入口继续讨论时，只切换参考项，不重建整套聊天系统。

Agent 回答与笔记互不覆盖，没有“替换正文”“一键应用修改”或自动生成笔记的入口。用户仍可使用正常复制粘贴。

### 长期关联

用户可以为可用的 Agent 关联单篇笔记或整个笔记本，也可在笔记侧查看、增加、解除关联。关联是“用户 + Agent + 来源”的关系，不存到共享 Bot 的全局配置里。

- 关联笔记本包含其子笔记本。新增、移入的笔记在下次请求中可被检索；移出后不再通过该笔记本获得访问范围。
- 单篇关联与笔记本关联取并集。同一笔记只检索一次；解除其中一种关联时，说明仍生效的其他来源。
- 关联不复制正文。每次请求按当前授权范围读取最新已保存版本，删除或放入回收站的笔记不参与。
- 回收站恢复后，尚存在的关联重新生效；永久删除时清除目标关系。删除笔记本清除该笔记本的关联，不把绑定自动转给父笔记本。
- 关联不授予新的 Agent 使用资格。用户失去该 Agent 的访问权限后，不得继续通过关联接口或聊天接口使用它。

## Agent 读取与引用

一次请求的来源范围为：会话临时参考的笔记，与当前用户对此 Agent 的长期关联笔记的并集。内部链接、标签和反向链接不会自动扩大授权范围。

后端核验用户、会话归属和 Bot 可用性，展开笔记本子树后取得可用笔记。客户端提供 ID，不能通过任意正文、所有者 ID 或请求里的路径绕过校验。选中片段是用户此次提问材料，与后端加载的原笔记来源分开记录。

首版使用数据库中的标题、正文与关键词筛选，按相关度选择有限片段。显式选中文字和当前笔记优先，其他关联资料按问题检索；设置总上下文预算，截断时保留段落边界并标记片段。相关度不足时说明没有找到相关内容，不声称读完全部笔记。确切预算和排序权重由实现者按当前模型限制决定，不作为新的用户配置。

如需 Agent 后续检索，工具只提供 `search_notes` / `read_note`，并绑定本次请求的用户、Bot 和允许读取的 ID 范围；所有入口使用同一来源解析服务。不存在任何笔记写工具，也不允许通用工具间接调用笔记写接口。笔记内容作为参考材料传入，不改变系统指令与工具权限。

来源记录至少包含笔记 ID、当时标题、版本、实际提供的片段及来源类型。后端生成有效来源标识，回答中的引用仅能解析到该请求实际提供过的标识；无效标识不能伪装为引用。区分“本次参考资料”和“回答引用”，前者表示提供给模型，后者表示回答明确引用，均不宣称来源内容必然正确。

引用显示笔记标题，可打开原文。笔记之后修改时，历史引用保留使用版本与片段，打开时说明当前正文可能已变化。删除或不可访问时不再展示实时正文，以不可用状态替代链接。

解除关联、删除笔记会停止未来的笔记检索，不回溯删除旧对话中的用户问题、回答和历史引用。每次请求重新装配参考上下文，不将旧片段作为永久系统上下文。旧回答仍可能影响同一对话，界面提示需要完全排除旧讨论时新建会话，避免承诺模型能“忘记”已经出现的内容。

笔记也不能经现有自动记忆提取变成所有 Agent 的共同知识。实现建议：标记使用过笔记的会话，首版将这些会话排除在 AgentMemory / mem0 自动提取和跨会话画像内容分析之外；不从引用 metadata 提取知识。保留普通对话原有机制，笔记只通过明确的参考范围进入后续请求。

## 数据与保存

独立 Django `notes` app，首版用关系模型表达：

| 对象 | 职责 |
| --- | --- |
| Notebook | 用户、父笔记本、名称、排序 |
| Note | 用户、笔记本、标题、正文、收藏、版本、删除时间、创建及更新时间 |
| Tag / NoteTag | 用户自己的标签及笔记归类 |
| NoteLink | 正文中解析出的有向链接，用于反向查询 |
| AgentNoteBinding | 用户、Bot、单篇笔记或笔记本的长期关联，二选一 |
| ConversationNoteReference | 用户、Bot、现有 Conversation、临时参考笔记 |

引用快照随现有 `AIChatMessage.metadata` 存储，避免新建聊天和引用历史系统。选中文字存在该问题的 metadata，不能当作整个会话始终有效的新来源。

正文以 Markdown 为唯一持久化内容，不并行维护会漂移的 Markdown / HTML / 编辑器 JSON 三套权威数据。内部链接使用带稳定 ID 的 Markdown 链接，编辑器提供 `[[` 选择交互；公式保存为 LaTeX。具体扩展由实现者确认与现有 Tiptap 的兼容性。

自动保存防抖、请求串行，更新携带版本号，后端原子比较并递增。迟到响应不能覆盖新笔记；切换笔记不会混入另一篇正文。多标签页版本冲突时保留本地文本并提示处理，不静默覆盖远端。失败和未保存状态可见，关闭或离开页面时提醒；不引入跨账号的 localStorage 草稿库。恢复功能首版指回收站恢复，不承诺完整历史版本恢复或浏览器崩溃后的离线恢复。

REST 写接口只服务经过认证、以用户操作发出的编辑请求。所有对象按 owner 过滤；机构教师及管理员不因其机构角色取得他人的私人笔记。沿用 Cookie 认证与现有权限 helper，序列化字段显式列出。笔记功能不隐含调整现有会员价格或套餐；实现建议允许有效登录用户管理自己的笔记，Agent 使用仍遵守原有 `ai.assistant` 资格和用量限制。

## 与当前代码的衔接（2026-10-22 本地核对）

- `frontend/src/components/MarkdownEditor.tsx`：已有 Tiptap 与 Markdown 序列化，可复用基础；当前有全局 `.ProseMirror` 样式且只设置初始内容，笔记使用须隔离样式并处理切换内容，不顺手改后台页面。
- `frontend/src/hooks/useAgentConversation.ts`：已有 `getExtraPayload`、稳定会话 ID、消息 metadata 与流式处理；参考笔记 ID 在这里随请求发送，切换与取消继续沿用现有保护。
- `frontend/src/components/AgentChatLayout.tsx` 和 `/xiaoyu` 页面：复用聊天与引用呈现，笔记中的讨论接入同一会话，不复制第二套聊天状态。
- `backend/ai_assistant/models.py`：已有 Bot、Conversation、AIChatMessage；关联到具体 Bot，但必须同时带用户归属。
- `backend/ai_assistant/services/chat_dispatch.py`：polling、SSE、WebSocket 共用运行时入口；同步与异步入口统一装配笔记上下文及来源。
- `backend/ai_engine/tool_permissions.py`：沿用现有工具权限机制，新增笔记检索仅授予只读工具，同时由执行器校验来源范围。
- 现有 `save_session_note` 保存的是 `StudySession.metrics.notes` 学习心得，不用于本功能；保留旧行为，不把它连接到独立笔记 app。

精确接口命名、模块拆分、查询优化与组件布局留给实现计划。不能为了首版建立通用文档平台、知识库插件框架、全新 RAG 服务或新 Agent。

## 首版不包含

多人协作与公开分享、Agent 写入或代建笔记、自定义数据库属性、表格与看板视图、模板市场、知识图谱画布、向量服务、完整离线同步、二进制附件和批量导入。这些都不是首版验收前提。

## 上线顺序与冒烟验收

1. 笔记模型、用户 API、编辑与组织入口，补充必要的数据库迁移。
2. 接入临时参考、长期关联、范围内检索与真实来源引用，覆盖当前支持的三个聊天入口。
3. 使用独立临时数据做冒烟：保存后重开；切换笔记不串正文；并发修改不覆盖；回收与导出；重命名不损坏链接；用户 A 无法读取 B 的笔记或绑定；Agent 不能写入；跨会话长期关联有效、临时参考不串会话；解除关联后新对话不再读取；实际引用可打开对应笔记。
4. 执行必要的 Django 检查、迁移检查和前端构建，不扩展成全量回归，不使用线上真实用户账户测试。
5. 部署前备份数据库，新增迁移采用增量方式；本地 commit / push 后按项目发布流程部署，先小范围开放再逐步放开。使用现有权限或运维配置控制试用范围，不建设独立灰度平台。
6. 上线验证区分本地、已推送与已部署：检查服务器版本、迁移、服务健康、公共页面资源与笔记入口。回滚关闭新增入口、恢复前一版本应用，新增数据保留，避免删表式回滚。

实现进度与验证记录见 `docs/superpowers/plans/2026-10-23-agent-linked-notes.md`。本地实现与生产发布分别验收。
